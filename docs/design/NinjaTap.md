# NinjaTap

只针对一台 HONOR DNY-NX9（Android 16，KernelSU）。电脑上的 Agent 通过本机 CLI 或 MCP 服务操作手机。手机上的 App 在拿到 root 之后，点一次开启，在后台提供截图和触控的 HTTPS 服务。

测量数值见 [DNY-NX9 实测](../devices/DNY-NX9.md)。触控轴、帧格式和真实手势的形状以那份记录为准。

## 1. 手机

App 包名 `com.ninjatap.player`。界面上设置端口、令牌和绑定地址。绑定地址列出 `0.0.0.0` 和当前的 IPv4，默认选无线网。选 `0.0.0.0` 时，状态行显示无线网地址，电脑用那个地址连接。播放器首次启动时生成自签名证书。私钥和证书保存在 App 的私有目录，界面显示证书的 SHA-256 指纹。

点开启后，App 调用 `/system/bin/su`，把 `phone/` 里的 aarch64 播放程序放到 `/data/local/tmp/ninjatap` 并执行。播放进程的域是 `u:r:ksu:s0`。通知栏留着监听地址。点停止就结束这个进程。

这个 App 要在 KernelSU（或同类的 root 管理器）里允许 root。允许之前，应用进程里看不到 `/system/bin/su`。允许之后如果应用还开着，划掉再打开。测量页 `com.ninjatap.touchtest` 不授予 root。

没有开机自启。重启之后，root 还在的话，打开 App 再点一次开启。

播放进程只做这些事：

- `GET /screencap`：`/system/bin/screencap -p -d <display-id>`，原样返回 1264×2736 的 PNG
- `POST /inject`：按序列写 `/dev/input/event6`
- 请求头 `Authorization: Bearer <令牌>`
- 灭屏或旋转不是 0 就拒绝，不写入
- 进程退出时如果还有触点，先写抬起

坐标是全帧像素。手机把像素乘 8，把电脑给的压力、长短轴和方向原样写入。手机不抽样，也不改这四个数。

手机在写入触控前检查整条轨迹的坐标，轨迹中的等待时间合计最多 15 秒。服务支持并发接收连接和读取请求。请求体最多 256 KiB，读取时限为 5 秒。截图、触控和剪贴板可以并行，每类同时最多执行一个请求。同类请求重叠时返回 `device busy`（HTTP 503）。如果需要手势完成后的画面，等手势命令返回后再截图。

失败时 `status` 为 `screen_off`、`rotation`、`no_device`、`closed`、`unauthorized`、`contact`。

## 2. 电脑

MCP 服务走 stdio，给本机 Agent 用。CLI 和 MCP 共享 HTTPS 客户端，配置项是 `NINJATAP_URL`、`NINJATAP_SECRET` 和 `NINJATAP_TLS_FINGERPRINT`。客户端在发送 Bearer 令牌前校验证书指纹。MCP 的标准输出只放 MCP 消息。Cursor 记下的是连上时的工具列表，重载步骤见 [README](../../README.md)。

工具：

| 工具 | 作用 |
| --- | --- |
| `screenshot` | 默认返回全帧 PNG；显式开启 OCR 时附上每个可读字符串的 id 和中心点。可再写到一个绝对路径 |
| `tap` | 点一个像素 |
| `taps` | 按顺序点多个像素，一次注入。每下重抽，中间空大约几十毫秒 |
| `long_press` | 按住大约给定的毫秒数 |
| `hold_drag` | 在起点停大约 `ms` 毫秒，不传则大约 500，不抬手，再拖到终点 |
| `drag` | 从一点拖到另一点，在终点停住再抬手 |
| `slow_drag` | 慢慢拖到终点，抬手时还在慢慢移动 |
| `flick` | 快速甩到终点，抬手时速度仍然很高 |
| `pinch` | 围绕一个中心，从起始间距变到结束间距 |
| `read_clipboard` | 读取剪贴板里的纯文本 |
| `write_clipboard` | 把一段文字写入剪贴板，不粘贴到输入框 |

文字识别在这台 Mac 上用 Vision 读全图，不缩放。Agent 自己看图和文字，自己决定点哪里。在这台机器上怎么点、怎么翻页，见 [操作这台手机](../operating.md)。

轨迹在调用这些工具时生成。点击大约 60ms，落点可以偏几个像素。`taps` 把多下这样的点击放进同一次注入，两下之间再空 40 到 110 毫秒，每下的接触分开重抽。一次最多 32 个点。长按时长偏开大约 8%，点会漂几个像素。按住再拖先在起点停大约 `ms` 毫秒，不传则大约 500，时长偏开大约 8%。手指不抬，再沿一条小弧拖到终点，停一下再抬。起点离左右边缘不到 140 像素就不会播放。拖动是一条小弧，先慢后快，再在终点停大约半秒。慢拖也是一条小弧，全程都在移动，抬手时大约 115px/s。快甩大约 250ms，速度逐渐加上去，最后一帧仍在快速移动时抬手。缩放不接收角度，角度、中心漂移和速度每次重抽，起止间距是给定的两个数。同一次操作每次的序列不同。

剪贴板由播放进程以 shell（uid 2000）调用 App 里的 `ClipboardCli`。Android 10 之后，后台应用可以写入剪贴板，读取只留给 shell、默认输入法或当前前台应用。读失败时状态是 `unavailable`，不是空字符串。

工具返回错误时，Agent 停下，不继续编下一个坐标。
